# 후방 2D LiDAR 논문 주차 실차 시험 체크리스트

대상 논문:

> H. K. Hong et al., “Automatic Reverse Parking Algorithm for
> Inter-Vehicle Spaces Using Rear 2D Lidar,” ICCE-Asia 2023.

이 문서는 논문 로직을 실차에서 처음부터 순서대로 확인하기 위한
절차다. 한 시험에서 여러 문제를 동시에 고치지 않는다. **가장 먼저
실패한 단계에서 시험을 중단하고 그 단계의 데이터만 분석한다.**

## 1. 시험 전 원칙

- [ ] 차량을 즉시 수동 정지할 담당자를 한 명 둔다.
- [ ] 디버그 화면 녹화를 먼저 시작한 뒤 프로그램을 실행한다.
- [ ] 가능하면 차량 전체가 보이는 외부 영상도 동시에 촬영한다.
- [ ] 디버그 화면과 외부 영상의 동기화를 위해 `SPACE`를 누르는 순간을
      두 영상에 모두 남긴다.
- [ ] 한 번의 시험에서는 설정값을 하나도 변경하지 않는다.
- [ ] 실패하면 같은 조건으로 반복하기 전에 CSV를 먼저 보존한다.
- [ ] A/B가 실제 두 차량을 향하지 않으면 후진을 계속하지 않는다.

## 2. 디버그 화면 읽는 방법

### 라이다 도형

- 굵은 노란 중심선: 차량 후방 `0°`
- 굵은 초록선: 왼쪽 `-90°`, 오른쪽 `+90°`
- 작은 자홍색 원: 논문의 `near_distance=600 mm`
- 큰 회색 원: C/D 유효 거리 `2,000 mm`
- 흰색 점: 일반 원시 LiDAR 반사점
- 파란 점: C 구간 `-100°~-70°`의 2m 이내 점
- 주황 점: D 구간 `+70°~+100°`의 2m 이내 점
- 자홍 점: 600mm 미만의 `is_near` 발생 점
- 빨간 A선: `Dist_A` 접선
- 노란 B선: `Dist_B` 접선
- 하늘색 선: `Angle_Bisector`
- C/D 글자가 붙은 원: 해당 구간에서 실제 최솟값으로 선택된 점

### 우측 정보

- `TIME`: 디버그 영상과 외부 영상을 맞출 시각
- `STATE`: 현재 논문 상태
- `MOTOR`: 실차 명령 활성 여부
- `CMD`: Arduino에 보낼 속도와 조향
- `WHY`: 현재 명령의 결정 이유
- `OBS`: 라이다 입력 상태
- `scanAge`: 현재 라이다 scan의 지연 시간
- `minRange`: 전체 논문 시야에서 가장 가까운 점
- `is_near`: 600mm 미만 점 존재 여부
- `countedCars`: 지금까지 센 우측 차량 수
- `right(D sector)`: D 구간에 2m 미만 점이 있는지
- `pair`: A/B 두 접점을 계산할 수 있는지
- `A`, `B`, `bisector`, `biasAB`: Figure 7 변수
- `angleTerm`, `distTerm`, `paperSteer`: 식 (2)~(5) 계산 결과
- `DistC`, `DistD`, `biasCD`: Figure 8 변수

`display=3000mm`는 화면 크기일 뿐 제어 범위가 아니다. A/B에는 별도
거리 상한이 없다. 우측 차량 검출과 C/D에만 논문대로 2m 제한이 있다.

## 4. 1단계: 출발과 직진 확인

실행:

```bash
PYTHONPATH=src python3 scripts/parking.py \
  --config configs/parking.json
```

디버그 녹화를 시작한 다음 `SPACE`를 한 번 누른다.

정상 기대값:

```text
STATE=search_first_car

countedCars=0
```

확인:

- [ ] `SPACE`를 누르기 전 차량은 정지한다.
- [ ] `SPACE`를 누르면 `speed=+80`, `steer=0`이 된다.
- [ ] 차량이 첫 차량을 향해 직진한다.

판정:

- 정상 직진 → 2단계로 간다.
- `MOTOR DISABLED` → `--no-motor` 없이 다시 실행한다.
- `waiting_for_rear_lidar` → 라이다 입력부터 수정한다.
- 논문 조향은 0인데 실제 차량이 왼쪽/오른쪽으로 감 → Arduino는
  변경하지 않고 `actuator_steering_offset`을 조정한다.
- 명령은 나오지만 출발하지 않음 → Arduino 포트, 모터 전원, `DRIVE`
  프로토콜을 확인한다.

### 직진이 한쪽으로 쏠릴 때 조향 중앙 보정

Arduino 펌웨어는 다른 주행 브랜치와 공유하므로 수정하지 않는다.
주차 브랜치의 다음 설정만 변경한다.

```json
"controller": {
  "actuator_steering_offset": 0
}
```

수정 파일:

```text
configs/parking.json
```

Arduino 조향 명령은 음수가 왼쪽, 양수가 오른쪽이므로:

- 차량이 **오른쪽으로 쏠림** → 왼쪽 보정이 필요하므로 offset을
  **음수**로 변경한다.
- 차량이 **왼쪽으로 쏠림** → 오른쪽 보정이 필요하므로 offset을
  **양수**로 변경한다.

예:

```text
오른쪽으로 쏠림: 0 → -10 → -15
왼쪽으로 쏠림:   0 → +10 → +15
```

처음에는 절댓값 `10` 단위로 방향을 찾고, 쏠림이 작아지면 `5` 단위로
미세 조정한다. 변경 후 프로그램만 다시 실행하면 되며 Arduino 재업로드는
필요 없다. 디버그의 `CMD`에는 offset이 적용된 최종 조향과 현재 offset이
함께 표시된다.

offset은 논문의 모든 이동 조향 명령에 마지막으로 더해진다.

```text
Arduino 최종 조향 = 논문 조향의 Arduino 변환값 + offset
```

최종 명령은 기존 Arduino 범위 `-150~+150`으로 제한된다. 예를 들어
offset이 `-10`일 때 논문 직진 0은 `-10`으로 전달되고, 논문 최대 좌조향
`-150`은 범위를 넘지 않도록 `-150`으로 제한된다.

중요한 구분:

- offset 0에서 앞바퀴가 한쪽을 향함 → 주차 설정 offset으로 보정
- 앞바퀴는 정확히 직선인데 차체가 계속 한쪽으로 감 → 타이어, 차축
  정렬 또는 좌우 구동 모터 출력 차이일 수 있다. 이때 offset으로 억지로
  보정하기 전에 기계 정렬과 좌우 바퀴 회전 차이를 확인한다.

### `0°`, `-90°`, `+90°` 라이다 기준선 확인 배치

모터 없이 차량을 고정하고 라이다 높이에 맞는 평평한 판이나 박스를
약 1m 거리에 놓는다.

1. 차량 정중앙 뒤쪽에 놓은 판 → 노란 `0° / REAR` 선 위
2. 라이다 기준 정확한 왼쪽에 놓은 판 → 초록 `-90° / LEFT` 선 위
3. 라이다 기준 정확한 오른쪽에 놓은 판 → 초록 `+90° / RIGHT` 선 위

세 물체를 동시에 놓아도 되지만, 어떤 반사점인지 헷갈리면 하나씩
이동하며 확인한다. 차량 범퍼 중심이 아니라 **라이다 렌즈 중심**을
거리와 각도의 기준점으로 사용한다.

판정:

- 뒤 물체가 0°에서 일정하게 벗어남 → `angle_offset_deg` 보정
- 왼쪽 물체가 +90°, 오른쪽 물체가 -90°에 나타남 →
  `clockwise_angles` 반전
- 뒤는 0°가 맞지만 좌우 물체 각도가 모두 90°에서 크게 벗어남 →
  물체 배치가 라이다 중심과 정확히 수직인지 다시 측정
- 세 방향 모두 맞음 → 각도 보정값을 더 이상 변경하지 않음

## 5. 2단계: 첫 번째 차량 검출

첫 번째 차량이 오른쪽 D 구간에 들어오면 정상 기대값:

```text
right(D sector)=True
countedCars=1
STATE=search_open_space
CMD speed=+80 steer=0
```

확인:

- [ ] 첫 차량 전에는 `right=False`, `countedCars=0`이다.
- [ ] 첫 차량 옆에서 처음 `right=True`가 된다.
- [ ] 첫 차량을 센 뒤에도 조향 0으로 계속 전진한다.

판정:

- 정확한 위치에서 `0→1` → 3단계로 간다.
- 첫 차량 전부터 `right=True` → 주황색 D 점이 무엇인지 확인한다.
  벽·신호등·사람이면 우측 차량 검출 문제가 첫 실패다.
- 첫 차량 옆에서도 `right=False`:
  - 차량 점이 `+70°~+100°` 밖 → 장착 각도 또는 우측 구간 문제
  - 구간 안이지만 2m 밖 → 논문의 2m 조건과 실제 배치 불일치
  - 점 자체가 없음 → 장착 높이 또는 반사 문제

첫 실패가 여기라면 A/B나 조향식은 아직 보지 않는다.

## 6. 3단계: 두 차량 사이 빈 공간

첫 차량이 D 구간에서 사라지면 정상 기대값:

```text
right(D sector)=False
countedCars=1
STATE=search_second_car
CMD speed=+80 steer=0
```

확인:

- [ ] 첫 차량을 지나면서 주황색 D 점이 사라진다.
- [ ] 빈 공간에서 `right=False`가 된다.
- [ ] 차량 수는 1로 유지된다.

판정:

- 정상 → 4단계로 간다.
- 빈 공간에서도 `right=True` → D로 표시된 점의 실제 물체를 확인한다.
- `True/False`가 빠르게 반복 → 원시 한 점 노이즈 여부를 CSV로 확인한다.
- 첫 차량이 사라지기 전에 `False` → 차량 옆면 검출이 끊긴 원인을 본다.

## 7. 4단계: 두 번째 차량 검출

두 번째 차량이 D 구간에 들어오면:

```text
right(D sector)=True
countedCars=2
```

확인:

- [ ] 빈 공간이 끝나고 실제 두 번째 차량에서만 `countedCars=2`가 된다.
- [ ] 그 순간 `is_near` 값과 `CMD`를 영상에 남긴다.

판정:

- 두 번째 차량에서 정확히 2 → 5단계로 간다.
- 빈 공간 안에서 2 → 노이즈를 두 번째 차량으로 센 것이다. 즉시 중단한다.
- 두 번째 차량을 지나도 1 → 두 번째 차량의 각도와 거리를 확인한다.

## 8. 5단계: 논문 초기 좌조향

두 번째 차량 검출 순간 `is_near=True`라면:

```text
STATE=prealign_left
CMD speed=+80 steer=-150
WHY=figure9_is_near_left_forward
```

`-150`은 논문의 조향 `-7`을 Arduino 범위로 바꾼 값이다.

확인:

- [ ] 두 번째 차량을 센 순간 `is_near=True`다.
- [ ] 실제 앞바퀴가 왼쪽으로 꺾인다.
- [ ] `is_near=True`인 동안 좌조향 전진이 유지된다.
- [ ] 600mm 미만 원인이 된 자홍색 점이 실제 차량 반사점이다.

판정:

- 정상 → 자홍색 점이 사라질 때 6단계로 간다.
- 두 번째 차량 검출 순간 `is_near=False` → 논문대로 좌조향 없이 바로
  후진한다. 현재 트랙의 시작 자세가 논문의 600mm 전제와 다른 것이다.
  이 상태에서는 시험을 중단하고 해당 scan을 먼저 분석한다.
- `steer=-150`인데 실제 우조향 → Arduino 조향 부호 문제다.
- 좌조향 직후 `is_near=False` → 처음 near를 만든 점이 일시적 노이즈인지
  확인한다.
- 계속 `is_near=True` → 자홍색으로 남는 물체가 무엇인지 확인한다.

## 9. 6단계: A/B와 이등분선

`is_near=False`가 되면 논문은 식 (2)~(5) 후진을 시작한다.

정상 기대값:

```text
STATE=reverse_align
pair=True
CMD speed=-80
```

확인:

- [ ] 빨간 A선이 한쪽 차량의 주차공간 안쪽 접점에 닿는다.
- [ ] 노란 B선이 반대 차량의 주차공간 안쪽 접점에 닿는다.
- [ ] 하늘색 이등분선이 두 차량 사이 공간을 향한다.
- [ ] A/B가 벽, 신호등, 사람 또는 같은 차량의 두 점을 잡지 않는다.
- [ ] A/B 값이 매 scan 갑자기 서로 다른 물체로 이동하지 않는다.

판정:

- 두 차량의 올바른 접점 → 7단계로 간다.
- `pair=False` → 한쪽 접점이 `±110°` 시야에 없는지 확인한다.
- A/B가 같은 차량 → 논문에서 생략된 차량별 점군 분리가 필요하다.
- A/B가 벽·신호등 → 범위를 넓히지 않는다. 물체 분리가 먼저다.
- 두 차량이 화면에 있는데 접점만 틀림 → A/B 원시점 선택이 첫 실패다.

A/B가 틀렸다면 후진 조향식의 결과도 무의미하므로 즉시 정지한다.

## 10. 7단계: 식 (2)~(5) 조향

확인:

- [ ] `biasAB=Dist_A-Dist_B`가 화면의 두 거리와 일치한다.
- [ ] `paperSteer`가 `-7~+7` 안에 있다.
- [ ] Arduino `steer`가 `-150~+150` 안에 있다.
- [ ] A/B 상대 위치가 변하면 조향도 실시간으로 변한다.
- [ ] 후진 방향이 주차공간 쪽으로 수렴한다.

판정:

- 정상 수렴 → 8단계로 간다.
- 계속 `±7`, `±150`에 포화 → 먼저 `biasAB`와 A/B 오검출을 확인한다.
- `paperSteer`는 맞지만 바퀴 방향이 반대 → Arduino 조향 부호 문제다.
- 조향이 매 scan 좌우로 급변 → A/B 원시점이 흔들리는지 CSV로 확인한다.

## 11. 8단계: 후진 중 near 정지

후진 중 어느 점이 600mm 안으로 들어오면:

```text
is_near=True
STATE=center_check
CMD speed=0
WHY=figure9_near_stop_and_check_dist_cd
```

확인:

- [ ] 실제 차량에 접근했을 때 자홍색 점이 나타난다.
- [ ] 같은 시점에 차량이 정지한다.
- [ ] 자홍색 점이 실제 어느 차량에서 발생했는지 영상에 보인다.

판정:

- 적절한 위치에서 정지 → 9단계로 간다.
- 너무 일찍 정지 → 자홍색 점의 각도와 실제 물체를 확인한다.
- 충돌 위험까지 정지하지 않음 → 즉시 수동 정지하고 장착 사각을 확인한다.

## 12. 9단계: C/D 중앙 정렬

정지한 화면에서 파란 C점과 주황 D점이 각각 양쪽 차량을 가리키는지
확인한다.

### C와 D가 모두 있고 `|C-D| < 250mm`

정상 기대값:

```text
STATE=reverse_straight
CMD speed=-80 steer=0
```

정상이면 10단계로 간다.

### C와 D가 모두 있고 `|C-D| >= 250mm`

논문 기대값:

```text
STATE=recovery_forward
CMD speed=+80 steer=0
```

3초 뒤 식 (2)~(5) 후진으로 돌아가야 한다.

### C와 D가 모두 `None`

논문대로 3초 전진 복구해야 한다.

### C 또는 D 하나만 `None`

논문이 이 상황을 정의하지 않았으므로 현재 코드는 다음 이유로 정지한다.

```text
paper_undefined_exactly_one_cd_none
```

이 경우 임의 동작을 추가하지 말고 해당 scan을 분석한다.

## 13. 10단계: 최종 후진과 종료

중앙 판정 후 기대값:

```text
STATE=reverse_straight
CMD speed=-80 steer=0
```

C 또는 D 하나가 `None`이 되면:

```text
STATE=parked
CMD speed=0
WHY=paper_dist_c_or_dist_d_none_finish
```

확인:

- [ ] 차량이 두 차량과 평행하다.
- [ ] 차량 전체가 주차공간 안에 있다.
- [ ] 너무 얕거나 너무 깊지 않다.
- [ ] `STATE=parked` 이후 계속 정지한다.

판정:

- 모두 정상 → 논문 로직 1회 성공
- 너무 얕게 정지 → C/D 한쪽이 너무 일찍 `None`이 된 원인을 확인한다.
- 너무 깊게 정지 → C/D가 계속 남는 센서 위치 문제를 확인한다.
- 평행하지 않은데 직진 후진 → 논문의 250mm 기준과 현재 차체 크기를
  비교한다.

## 14. 시험 종료 후 반드시 보존할 자료

프로그램은 실행마다 `data/parking_v2/`에 다음 파일을 만든다.

```text
<시간>_lidar.csv
<시간>_paper.csv
```

한 시험을 분석할 때 다음 네 가지를 같은 묶음으로 보낸다.

1. 디버그 창 전체가 보이는 화면 녹화 MP4
2. 가능하면 차량과 두 주차 차량이 모두 보이는 외부 촬영 MP4
3. 같은 시각의 `_lidar.csv`
4. 같은 시각의 `_paper.csv`

함께 알려줄 내용:

- 시험 시작 시각
- 처음 예상과 달라진 영상 시각
- 그 순간의 `STATE`, `WHY`
- 수동으로 막거나 차량을 잡은 시점
- 사람 또는 다른 물체가 라이다 주변에 있었는지
- 첫 차량과 두 번째 차량의 배치가 이전 시험과 달랐는지

영상이 길어도 괜찮다. “몇 초에서 첫 실패가 발생했는지”가 있으면 그
직전과 직후의 라이다 raw scan과 논문 변수를 정확히 비교할 수 있다.
